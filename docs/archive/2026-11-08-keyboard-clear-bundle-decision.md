# 清除键盘记录入口的体积预算

设置页的「记录键盘活动」已能开启采集，但关闭开关只会停止记录，已经写入数据库的击键汇总仍然保留。新增加的「清除键盘记录」入口把删除动作放到同一个设置分组里，确认后调用 `cmd_clear_keyboard_activity` 清空两张键盘汇总表。删除本身在 Rust 侧早已就位，这次只补前端入口、确认流程与三种语言的文案。

## 同环境测量

使用项目锁定的 Node 24.22.1、Vite 8.2.4、现有锁定依赖和预算脚本的 Node gzip 口径，在同一个工作区对同一份改动做两次生产构建：先把工作区改动 stash 后构建出对照产物，再恢复改动重建。两次构建共用同一份 `node_modules` 与 `dist` 目录，仅在 `dist` 之后按预算脚本口径计量。

## 成本归属

`keyboardActivityGateway` 是新增的共享按需模块。它此前只被数据页的热力图读取，现在设置页的删除动作也要调用同一个类型化网关，于是它从「被单个页面顺带打包进 Data 分块」变成「被两个互不加载的懒加载页面共同引用」，Vite 只能把它提升成独立分块。该分块实测 0.18 KiB，已在 `LAZY_SHARED_UI_CHUNK_BUDGETS` 单列 owner，不再落入未归属的 support 聚合。

Settings 页面的 0.17 KiB 是确认流程、按钮与状态位的直接成本；settings runtime adapter 的 0.04 KiB 是把网关调用转一手的类型层，这一层由架构边界强制——feature 的组件与 hook 不允许直接 import `src/platform`，必须经 feature service 转发。四种语言的文案各增约 0.04 KiB，合计三条消息（一条提示与两条结果提示）。

`KeyboardHeatmapSection` 反而减少了 0.05 KiB：本次同时修掉了热力图每次渲染都重算时间范围导致的重复请求死循环，范围解析改为由调用方传入固定的 `nowMs`，纯函数搬进独立的 `keyboardHeatmapRange.ts`，面板里重复的时钟项消失。

## 减重排查

三条新消息已压缩到最短可读长度，并把确认弹窗的描述复用为入口提示，避免再增加第四条消息；删除动作复用既有的 `dialog.confirmDanger` 与 Quiet Pro 按钮，没有新增组件。删除流程抽成纯函数 `runKeyboardClearFlow` 放在已有的 `settingsPageActions.ts` 里，没有引入新文件或新依赖。

网关不能内联到任一调用方：数据页与设置页在路由上互斥加载，任何一侧内联都会让另一侧重复打包同一份命令封装，反而更大。删除动作也不能直接写在组件里调用 Tauri 命令，那是架构边界明确禁止的方向。

## 预算决定

经维护者确认，总预算由 426.2 调至 426.9 KiB，增加 0.7 KiB（0.16%），保留 3% 预留后有效上限由 423.335 调至 424.031 KiB。本地化运行时预算由 7.8 调至 7.85 KiB（+0.05 KiB，0.64%），有效上限由 7.747 调至 7.797 KiB。两处调整只覆盖确认必要的增量，剩余缓冲分别为 141 B 与 47 B。

本次只调整上述两个预算。Settings、Data、Keyboard heatmap、settings runtime adapter 与四种语言块继续采用各自现有上限，均未同步放宽。本次未重建正式发布产物，不更新或推断发布基线。
